# tglog

**Пост-ченджлоги для Telegram-канала в твоём стиле**<br>
Один раз учит стиль канала, дальше пишет посты по git-коммитам проекта

Сначала один раз изучает канал и запоминает, как ты пишешь. Потом по команде делает черновик поста для выбранного проекта. В канал публикует только после твоего подтверждения.

## Команды

| Команда | Что делает |
|---|---|
| `python tglog.py learn @канал` | Скачивает последние 100 текстовых постов канала, просит Claude описать твой стиль (`style.md`, до 300 слов) и выбрать 8 самых типичных постов (`examples.json`). Нужна один раз. |
| `python tglog.py post /путь/к/проекту` | Берёт коммиты с последнего git-тега (или последние 30, если тегов нет) и пишет пост-ченджлог. |
| `python tglog.py new /путь/к/проекту` | Для нового проекта без коммитов: читает README и список файлов (сам код не читает) и пишет пост-анонс. |

После черновика в терминале нужно выбрать: **1** — опубликовать, **2** — переделать (с твоим комментарием), **3** — отмена.

## Установка

Нужен Python 3.9 или новее (в Kali Linux он уже есть).

```bash
git clone https://github.com/ТВОЙ_НИК/tglog.git
cd tglog
python3 -m venv venv
source venv/bin/activate
pip install telethon anthropic
cp .env.example .env
nano .env
```

В каждом новом терминале сначала нужно зайти в папку и включить окружение:

```bash
cd tglog && source venv/bin/activate
```

## Ключи

В файл `.env` нужно вписать три значения:

```
TELEGRAM_API_ID=
TELEGRAM_API_HASH=
ANTHROPIC_API_KEY=
```

- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH`: сайт [my.telegram.org](https://my.telegram.org) → API development tools → создать приложение.
- `ANTHROPIC_API_KEY`: Claude Platform ([platform.claude.com](https://platform.claude.com)) → API keys.

## Первый запуск

```bash
python tglog.py learn @твой_канал
```

Telegram спросит номер телефона и код из приложения. Если у тебя включён облачный пароль, спросит и его (символы при вводе не видны, это нормально). После входа рядом появится файл `tglog.session`, и в следующий раз вводить ничего не придётся.

Чтобы публиковать посты, этот аккаунт должен быть админом канала с правом публикации.

## Как экономятся токены

- Стиль анализируется один раз, дальше используется только короткий `style.md`.
- Для поста в Claude (`claude-haiku-4-5`) уходит только: стиль, 3 примера и список названий коммитов. Диффы и содержимое кода не читаются.
- Мусор отбрасывается: merge-коммиты, коммиты только с lock-файлами, `node_modules`, `dist`, `build`.
- Ответ не длиннее 500 токенов (кроме `learn`: там 1200, иначе 300 слов по-русски не влезут).
- «Переделать» отправляет только черновик и твой комментарий.
- Prompt caching включён, но у Haiku 4.5 он работает только от 4096 токенов в начале запроса. Если стиль и примеры короче, кэш молча пропускается, это не ошибка.
- После каждого запроса скрипт печатает, сколько токенов потрачено и сколько взято из кэша.

Модели прописаны в начале `tglog.py` (`SONNET` и `HAIKU`), при желании их можно поменять.

## Какие файлы появляются

| Файл | Что это |
|---|---|
| `.env` | Твои ключи. **Секрет.** |
| `tglog.session` | Вход в твой Telegram-аккаунт. **Секрет.** |
| `posts.json` | Скачанные посты канала. |
| `style.md` | Описание твоего стиля. |
| `examples.json` | 8 типичных постов (в запрос берутся первые 3). |
| `channel.txt` | Канал, в который публикуются посты. |

В репозиторий нужны только `tglog.py`, `.env.example`, `.gitignore`, `README.md` и `logo.png`. Файлы `.env` и `*.session` никуда не отправляй, `.gitignore` их уже исключает.

## Если что-то не работает

- **«Нет файла .env»**: выполни `cp .env.example .env` и впиши ключи.
- **«Сначала нужно изучить канал»**: запусти `learn`.
- **«Канал не найден»**: проверь имя, оно должно начинаться с `@`.
- **«В этот канал нельзя писать»**: аккаунт должен быть админом канала с правом публикации.
- **«Нет новых коммитов»**: после последнего тега в проекте ничего не менялось.
